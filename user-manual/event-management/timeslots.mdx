title: 'Timeslots'
description: 'Split events into specific admission windows with independent stock, on-sale rules, and visibility controls.'
---

## Overview

- Timeslots divide an event into distinct admission windows, each with its own date/time range, stock, on-sale period, and visibility settings.
- Timeslots are managed from the event dashboard under **Manage time slots**.
- Timeslot names support [translations](/user-manual/core/translations), allowing localised labels per language. When no name is set, the configured time display format is used instead.
- For seated events, creating a timeslot automatically creates the corresponding [seating plan](/user-manual/event-management/seated-events) spaces for that slot.
- All timeslot dates respect the event's [timezone](/user-manual/core/timezones) and must fall within the event's start and end dates.

<Note>
  Timeslots require the timeslots feature to be enabled for your company. Users
  need timeslot permissions (create, edit, delete) along with event edit and
  edit-relationship access.
</Note>

## Use Cases

<Accordion title="Timed entry for attractions">
  A theme park or visitor attraction manages crowd flow by offering timed entry
  slots — for example, every 30 minutes from 9am to 5pm. Each slot has its own
  capacity, and the repeat interval generates all slots automatically. **Hide
  when sold out** keeps the page clean as slots fill up.
</Accordion>

<Accordion title="Multi-day festival with day passes">
  A three-day festival uses daily timeslots so customers purchase entry for
  specific days. Each day has its own stock, allowing capacity to be managed
  independently per day.
</Accordion>

<Accordion title="Guided tours with scheduled departures">
  Walking tours depart every hour with a fixed group size of 15. Hourly
  repeating timeslots enforce the group limit per departure. Customers can
  filter by time of day to find a convenient tour.
</Accordion>

<Accordion title="Workshops and classes with limited places">
  A venue runs pottery classes at 10am, 2pm, and 6pm. Each session has a limited
  number of places. Different ticket types (adult, child) can be created within
  each timeslot, and the timeslot stock ensures total attendance per session
  stays within the instructor's capacity.
</Accordion>

<Accordion title="Exhibition with optional timed viewing">
  An exhibition offers timed viewing slots for peak hours but also sells general
  admission tickets for the full day. Timeslotted tickets manage peak-hour
  capacity, while non-timeslotted tickets are sold as
  [event passes](#event-passes) for visitors who prefer flexible entry.
</Accordion>

## Creating Timeslots

Use **Create a time slot series** from the timeslot management page to generate one or more timeslots.

### Core Fields

| Field                         | Description                                                                                                |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------- |
| **Name**                      | Optional. Supports multiple languages. When omitted, the display falls back to the configured time format. |
| **Validity dates**            | Required start and end date/time. Must fall within the event's start and end dates.                        |
| **Repeat**                    | One-off, or repeating at an interval: minutes, hourly, daily, weekly, monthly, or annually.                |
| **Repeats every**             | Interval between repeats (`1`–`60`). Only shown when a repeat option is selected.                          |
| **Generate time slots until** | End boundary for generation. Defaults to the event end date/time.                                          |

### Advanced Options

| Field                      | Description                                                                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Time slot stock**        | `Unlimited` (no cap) or `Limited to` a specific number. See [Stock Rules](#stock-rules).                                                                |
| **Sale items**             | Selecting items creates new [sale item](/user-manual/sale-items/core-concepts) instances in each generated timeslot. Existing items are not modified. |
| **On sale dates**          | Optional start and end dates controlling when the timeslot is available for purchase.                                                                   |
| **Hide when off-sale**     | Hides the timeslot when outside its on-sale period or after it has ended.                                                                               |
| **Hide when out-of-stock** | Hides the timeslot when stock is exhausted.                                                                                                             |

### Scheduled Events

For events that belong to a [schedule](/user-manual/event-management/schedules), the creation form offers the option to create equivalent timeslots on other upcoming events in the same schedule. Timeslot dates and on-sale dates are adjusted relative to each target event's dates.

### Limits

Each event has a maximum number of timeslots, controlled by a company setting (default: `30`). The creation form displays the remaining capacity and blocks submission if the generated timeslots would exceed it.

<Warning>
  Timeslots can't be created on a [seated event](/user-manual/event-management/seated-events)
  that already has [season tickets](/user-manual/sale-items/season-tickets) — an event can have
  any two of timeslots, season tickets, and a seating plan, but not all three. When creating
  timeslots across a schedule, seated events with season tickets are skipped and listed in a
  warning. See [Season Tickets on Timeslot Events](/user-manual/sale-items/season-tickets#season-tickets-on-timeslot-events).
  <Tip>Timeslots on events with season tickets added in Release 47</Tip>
</Warning>

## Managing Timeslots

### Admin View

The timeslot management page displays timeslots in a calendar view with weekly and daily pagination. Each timeslot shows:

- Name and display time
- Capacity bar (sold, reserved, remaining)
- Sale status (on sale, off sale, sold out)
- Quick actions: add tickets, toggle sale status, delete

Timeslots can be reordered via drag-and-drop. The sort order determines the display sequence in the shop.

### Editing a Single Timeslot

Open a timeslot from the calendar view to edit its name, dates, stock mode/quantity, on-sale dates, visibility toggles, and assigned sale items.

<Note>
  If your role only allows stock edits after publish, timeslot fields become
  read-only while stock remains editable.
</Note>

### Toggling Sale Status

The timeslot list provides a quick toggle to take a timeslot on or off sale without opening the full edit form.

### Bulk Updating

From the edit view, use **Edit time slots** to apply changes across multiple timeslots.

**Scope** — which timeslots to target:

- **Just this time slot**
- **Time slots within this event**
- **Time slots within this schedule** (if the event belongs to a schedule)

**Filters** — narrow the target set:

| Filter         | Options                                                                               |
| -------------- | ------------------------------------------------------------------------------------- |
| **Scope**      | All time slots, Future time slots, Past time slots                                    |
| **Time**       | All time slots, All time slots matching minutes past, Time slots with this exact time |
| **Comparison** | All time slots, Time slots before, Time slots after                                   |

When more than `100` matches are found, individual rows are not listed but criteria-based updating is still supported.

On-sale dates in bulk updates are adjusted relative to each target timeslot's existing on-sale dates. If the source or target timeslot does not have on-sale dates, the specified date is applied directly.

### Overwriting from the Event Dashboard

Timeslots can also be edited in bulk from the event dashboard. Select one or more timeslots from the list and click **Edit** to open the overwrite modal. This presents a blank form — only the fields you modify are applied to the selected timeslots.

### Deleting Timeslots

<Tabs>
  <Tab title="No Orders or Reservations">
    The timeslot and its assigned sale items are deleted.
  </Tab>
  <Tab title="Existing Orders or Reservations">
    The timeslot is kept but its sale items are taken off sale. A warning is
    shown in the admin.
  </Tab>
</Tabs>

Deleted timeslots are soft-deleted and can be restored.

## Shop and Box Office Behaviour

### Visibility and Sale State

A timeslot is purchasable when all of the following are true:

1. The event is on sale.
2. The timeslot is within its on-sale period.
3. The timeslot has not ended.
4. There are visible sale items with available stock for the timeslot.

Timeslots that are sold out or off sale appear greyed-out with a **Sold Out** or **Off Sale** badge.

### Hide Rules

- **Hide when off-sale** — removes the timeslot from view when it is outside its sale period or after its end time.
- **Hide when out-of-stock** — removes the timeslot from view when stock is exhausted.

### Selecting a Date and Time

<Tip>Redesigned in Release 47</Tip>

When the timeslot selection UI is enabled as an [early access feature](/user-manual/ticket-shop/shop-settings#early-access-features), customers choose a date and time through a simplified, step-by-step flow that also covers [scheduled events](/user-manual/event-management/schedules). The same flow handles both single-day timeslotted events and longer schedules.

**Choosing a date.** Customers first pick a date. Dates are listed in date order, and events on the same day in order of their start time. When there are fewer than 10 dates, they're shown as a single list grouped under month headings (**Select date**). With 10 or more dates spread over several months, dates are shown a month at a time: customers move between months using the **previous** and **next** month arrows, or use **View other months** to pick from the **Select month** list. The selector opens on the event's own month — or the first month with dates, if the event's month has none — but starts on the **Select month** list when the event's date has already passed, or when the opening month has only one date while another month offers more. When every date falls in the same month, there's no month step at all: the dates are listed straight away under the month's name. <Tip>Single-month schedules skip the month step in Release 47</Tip> Each entry shows how many dates or slots it contains, or **Sold out** when nothing is available.

**Choosing a time.** After selecting a date, customers choose a timeslot. When a day has many timeslots spread across the day, they are grouped into segments:

| Segment             | Covers        |
| ------------------- | ------------- |
| **View all times**  | The whole day |
| **Morning**         | Until midday  |
| **Afternoon**       | From midday   |
| **Evening**         | From 5pm      |

Selecting a segment shows just those times, with **View all timeslots** to see the full day. Customers can step through dates without leaving the time view using the **Previous date** and **Next date** arrows, and use the top-left link to go back — **View day segments** when a segment is open, or **View other dates** to return to the date list. When a day has only a few timeslots, the segments are skipped and the times are listed directly.

**Sold-out indicators.** Timeslots, days, and day segments that are unavailable stay visible but appear greyed out and cannot be selected. They are labelled **Sold out** when stock is exhausted, or **Off sale** when outside their on-sale period.

<Note>
If the available dates and times cannot be loaded, customers see the message *We could not load the available dates and times. Please try again.* with a **Try again** action. Months that have already loaded stay available while the failed request is retried.
</Note>

#### Dates With a Single Time

<Tip>Single-time dates skip the time step in Release 48</Tip>

When a customer picks a date that has only one timeslot they can buy — whether on a single event or across the events in a [schedule](/user-manual/event-management/schedules) — there is nothing left to choose, so the time step is skipped: that timeslot is selected for them and they go straight to choosing tickets. Sold out and off sale timeslots don't count towards this, so a date with only one timeslot still available is skipped too.

The list of times is still shown when:

- The event also offers [event passes](#event-passes) — **Whole Event** is always a second option alongside the day's time.
- The customer arrives at the date using the **Previous date** and **Next date** arrows, so they can keep stepping through the times on each day.

### Display Format

The event setting **Display timeslot** controls how timeslot times are rendered to customers:

| Option                        | Behaviour                         |
| ----------------------------- | --------------------------------- |
| Display start & end times     | Shows both the start and end time |
| Display start, hide end times | Shows the start time only         |
| Display end, hide start times | Shows the end time only           |
| Hide start & end times        | No time is displayed              |

Each timeslot also shows its lowest price when visible in the shop.

#### Times Alongside Named Timeslots

<Tip>Added in Release 47</Tip>

In the redesigned selector, a timeslot that has a [name](#core-fields) now also shows its start and end time on a second line beneath the name. Previously only the name was shown, which made slots indistinguishable when every timeslot shared the same name (for example, several "Entry timeslot" slots that differ only by time). Timeslots without a name continue to show their start and end time as the main label.

### Event Passes

An **event pass** is a ticket on a timeslotted event that is not assigned to any timeslot — it covers the event as a whole rather than one slot, which suits customers who want entry without committing to a particular time. Whenever an event has both timeslotted and non-timeslotted sale items, the shop offers event passes alongside the real timeslots so both can be bought from the same place.

In the timeslot picker the option is headed **Event pass**, with **Whole Event** in place of a time underneath. The [redesigned selector](#selecting-a-date-and-time) puts it first in each day's time list, labelled **Whole Event** with the event's dates beneath.

<Note>
**Event pass** is the platform's name for the ticket; **Whole Event** only ever labels the option that holds them. Admin uses the same wording throughout — **This item is an event pass** on the seating plan, **Apply as event pass** and **Select all event passes** when bulk editing, and **Event pass** in the seating plan legend. The customer-facing label can be reworded for your own shop through [website text](/user-manual/cms/website-text), so your customers may see something different.
</Note>

Event passes have no timeslot to draw a validity window from, so they keep their own [check-in times](/user-manual/event-management/access-control#check-in-time-options) and are admitted differently from timeslot tickets — see [Admitting Timeslot Tickets](#admitting-timeslot-tickets).

### Box Office

[Box office](/user-manual/box-office/introduction) users can view and interact with timeslots that are hidden or off-sale on the public shop, allowing sales outside the normal visibility rules.

## Stock Rules

- **Unlimited** — no timeslot-level sales cap is applied.
- **Limited** — a specific sales cap for the timeslot. Total stock cannot be set below the sum of already sold and reserved quantities; current stock is recalculated as total minus sold and reserved.
- Effective saleability is the **minimum** of the timeslot's own stock and the stock of its assigned sale items. Both must have availability for a purchase to succeed.

## Admitting Timeslot Tickets

Timeslots decide *when* a ticket is valid for entry, not how entry itself is controlled. [Access control](/user-manual/event-management/access-control) still works through zones: every scan is recorded against a zone and a ticket, and no scan counter is kept per timeslot.

- **Timeslot tickets** take their [validity window](/user-manual/event-management/access-control#validity-dates) from the timeslot's start and end times, extended by any grace period on the sale item. Scanning one outside its slot is rejected — [Access Control Pro](/mobile-apps/access-control-pro/introduction) shows **Not yet valid** or **No longer valid** and offers no admit button.
- **[Event passes](#event-passes)** keep their own check-in times, so they are valid whenever those times allow rather than being tied to a slot.
- **Re-entry** is governed by the zone's [scan limit](/user-manual/event-management/access-control#scan-limits), which counts scans across the whole event. An event pass scanned into a **single access** zone admits once for the event, not once per timeslot; in an **unlimited access** zone it can be re-scanned throughout, covering every timeslot.

For the full picture — including how to override validity checks and why a zone cannot be restricted to a single slot — see [Timeslots and Event Passes](/user-manual/event-management/access-control#timeslots-and-event-passes).

Attendance can still be broken down by slot after the event. The [scanning report](/user-manual/reporting/default-reports#scanning-reports) carries the timeslot name and its start and end dates against each scan, leaving those columns empty for event passes.

## Related Constraints

- Timeslotted sale items cannot be associated with [sale item groups](/user-manual/event-management/sale-item-groups).
- If event dates are changed after creating timeslots, the admin flags out-of-bounds timeslots so they can be corrected.
