## Overview

A schedule is a group of related events. Schedules enable:

- Grouping events for display on a dedicated schedule listing page
- Allowing customers to browse dates via a calendar interface
- Selling [season tickets](/user-manual/sale-items/season-tickets) that grant access to all events in the schedule

Schedules can be created in two ways:

1. **Linking standalone events** — Attach multiple separate events together into a schedule
2. **Creating repeating events** — Turn a single event into a repeating series (see [Creating Repeating Events](#creating-repeating-events))

These approaches can be combined: standalone events can be attached to existing repeating series and vice versa.

### Adding Existing Events to a Schedule

1. Open the schedule dashboard by clicking **Create schedule** or **Manage schedule** on the event dashboard.
2. Open the **Schedule help** window. It opens automatically when the event isn't in a schedule yet; on a mixed events schedule, click **Add events**.
3. Open the **Attach existing event** tab and click **Attach existing event**.
4. Choose the event from **Select existing event**, then click **Add to schedule**.

On a repeating events schedule, **Add events** opens the **Schedule repeats** modal instead — see [Creating Repeating Events](#creating-repeating-events).

Only events that haven't ended and aren't already in a schedule are listed. Each is shown with its start and end date and time, so events on the same day — such as a matinee and an evening performance — can be told apart. <Tip>Event times added to the event list in Release 47</Tip>

### Removing Events from a Schedule

Individual events can be removed from a schedule (unscheduled), reverting them to standalone events. If a schedule is reduced to fewer than two events, the schedule is automatically deleted.

## Schedule Types

Every schedule has a type that determines how events are displayed to customers:

| Type                 | Description                                                                                                                                    | Use Case                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **Mixed events**     | Events are related but unique. A dedicated schedule listing page displays all events, allowing customers to navigate between dates.            | Theatre productions with different shows, festival days with different lineups |
| **Repeating events** | Events are identical. A schedule calendar appears in the ticket selection modal, letting customers browse available dates from any event page. | Weekly classes, recurring tours, regular performances                          |

<Note>
  Mixed event schedules always have a listing page. Repeating event schedules
  can optionally enable a listing page.
</Note>

## Schedule Listing Page

The schedule listing page is a customer-facing page that displays all events in the schedule.

### Profile Settings

| Field                    | Description                                                                                                                             |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |

| **Description**          | Rich text content for the schedule listing page body                                                                                    |
| **Enable listing dates** | When enabled, the schedule's overall start and end dates appear in the page header                                                      |
| **Default list style**   | The initial view when customers land on the page: **List view** or **Calendar view**. Customers can switch between views after loading. |

| **Schedule header image**        | Displayed at the top of the schedule listing page                                                                                                               |
| **Show header image full width** | When enabled, the header image spans the full width of the screen                                                                                               |

| Field                | Description                                                                              |
| -------------------- | ---------------------------------------------------------------------------------------- |

For schedules that offer [season tickets](/user-manual/sale-items/season-tickets), you can customise the badge text displayed during checkout. By default, this shows "Season ticket".

## Schedule Groups

Schedule groups (also called sub-schedules) allow you to organise and subdivide larger schedules into logical sections. Each group appears as a tab on the schedule dashboard, making it easy to manage subsets of events independently.

This is particularly useful for schedules with many events where certain events share characteristics — for example, grouping weekend performances separately from weekday ones, or organising a festival schedule by stage or genre.

### How Groups Work

- Each group has a **name** that appears as a tab on the schedule dashboard
- An event can belong to **only one group** at a time, but can be moved between groups freely
- Events not assigned to any group appear under the **Ungrouped** tab, which is always the first tab
- Group names support [translations](/user-manual/core/translations), so they can be localised for multi-language shops
- Groups can optionally be made visible to customers in the shop — see [Showing Groups in the Shop](#showing-groups-in-the-shop)

### Creating a Schedule Group

1. Navigate to any event in the schedule and open the **schedule dashboard**
2. Select **Create sub schedule tab** from the tab actions
3. Enter a **name** for the group
4. Select the **events** you want to include — only upcoming events from the current schedule that are not already in another group are available
5. Optionally enable **Group is visible to customers** to display the group name during date selection in the shop
6. Save the group

The new group appears as a tab on the schedule dashboard immediately.

### Showing Groups in the Shop

By default, schedule groups are an admin-only organisation tool — customers don't see which group an event belongs to. You can change this per group with the **Group is visible to customers** toggle in the group's settings.

The toggle's help text reads: *"When enabled the name of the schedule group will be displayed to the customer during date selection."*

When enabled, the group name appears alongside each scheduled event in the shop's date and event selection UI. This is useful for communicating context that helps customers pick the right date — for example, labelling shows as **Matinee**, **Evening**, or **VIP** so customers can see at a glance which type of performance each date corresponds to.

Each group's visibility is independent: you can keep some groups internal while exposing others, and toggling visibility doesn't affect which events belong to which group.

### Editing a Schedule Group

1. On the schedule dashboard, navigate to the tab for the group you want to edit
2. Select **Edit sub schedule tab** from the tab actions
3. Update the group **name** or change which **events** belong to the group
4. Save your changes

<Note>
  When you deselect events during editing, they return to the **Ungrouped** tab — they are not deleted.
</Note>

### Deleting a Schedule Group

1. On the schedule dashboard, navigate to the tab for the group you want to remove
2. Select the delete action and confirm
3. All events in the group return to the **Ungrouped** tab

### Bulk Editing with Groups

When [bulk editing](/user-manual/utilities/bulk-editing) events in a schedule, you can scope changes to:

- **All events** in the schedule
- Only events in a **specific sub-group**
- Only **ungrouped** events

This lets you make targeted changes — for example, adjusting ticket prices for all weekend events without affecting weekday events.

## Creating Repeating Events

Repeating events copy one event onto a series of new dates within the same schedule. You can set them up in two places:

- **While creating an event** — turn on **Repeat event** under **Event dates** in the **Location & Dates** step of the [event creation wizard](/user-manual/event-management/introduction#creating-events). The event you are creating is always part of the list, using the dates from **Event dates**, and all of the dates are grouped into a **Repeating events** schedule. When you save, the event is created and the other dates are queued for creation in the background — you are taken to the schedule dashboard with the message *Your event has been created and future dates have been queued for creation.*
- **From an existing event** — open the schedule dashboard (**Create schedule** or **Manage schedule** on the event dashboard) and click **Add events**. On a repeating events schedule this opens the **Schedule repeats** modal directly; on a mixed events schedule, or for an event that isn't scheduled yet, choose **Schedule new event** first. The modal shows the **Event to be repeated** — click **Edit** to search for a different event in the schedule to use as the template.

Both use the same controls to choose the dates.

### Repeat Cycle

| Cycle        | Description                                                                                                                  |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| **Daily**    | Repeat every _n_ days (e.g., every day, every 2 days)                                                                        |
| **Weekly**   | Select specific days of the week (e.g., every Tuesday and Thursday)                                                          |
| **Monthly**  | Select specific dates of the month (e.g., the 1st and 15th). Only dates 1-28 are available to ensure validity in all months. |
| **Annually** | Once per year on the selected date                                                                                           |
| **Custom**   | Hand-pick specific dates from a calendar                                                                                     |

### Repeat Window

- **Repeat start window**: The date from which repeats should begin. Only shown in the **Schedule repeats** modal — when creating an event, repeats follow on from the event's own dates.
- The end of the window is either:
  - **Repeat ends on or before** — an end date, or
  - **Repeat ends after** — a number of events (e.g., repeat for 30 events)

<Warning>
  Each repeat action can create a limited number of events — 31 unless your
  account manager has set a different limit for your account. The limit is
  shown as **Maximum** beside **Repeat ends after**. For larger schedules, add
  repeats in batches.
</Warning>

### Adjusting Individual Dates

<Tip>Custom times for repeat events added in Release 48</Tip>

The dates you choose are listed under **Events to be scheduled**, each with its **Start** and **End** date and time, and a **Total** count (plus a **Remaining** count once you are close to the maximum). Every date can be changed on its own, so repeats don't have to share the original event's times — for example, to create a matinee and an evening performance on the same day in one go.

To change a date:

1. Click **Edit** on its row. The **Start** and **End** become date and time fields.
2. Set the date and times for that occurrence.
3. Click **Done**.

To remove a date, click the delete (bin) icon on its row.

Editing or removing a date that was generated by a daily, weekly, monthly, or annual cycle switches the **Repeat cycle** to **Custom**, keeping every date already in the list, so your changes are not overwritten by the cycle.

With **Custom** selected, there are two ways to add dates:

- **Pick from the calendar** — each date you click adds an event on that day at the original event's start time and duration. Clicking a date that is already in the list adds another event on that day, which you then edit to a different time.
- **Add date** — adds an empty row ready for you to enter its start and end.

When creating an event, its own row can't be edited or removed here — change it with **Event dates** instead.

Each row is checked as you edit, and you can't move on (**Next**, or **Save as draft** in the wizard) until every row is valid:

| Message | Cause |
| ------- | ----- |
| *Enter both a start and end date and time.* | The row is missing a start or an end |
| *The start date and time must be in the future.* | The start has already passed |
| *Each repeat event needs a unique start time.* | Another row starts at the same date and time |
| *The end date and time must be after the start date and time.* | The end is not after the start |

### What Gets Copied

When adding repeats with the **Schedule repeats** modal, the next step lets you select which elements to copy from the original event:

- **Sale items** (tickets, add-ons) — Copied items retain a reference to the original, allowing bulk editing and rebooking across the schedule
- **Seating plan** — The seating configuration is replicated
- **Sale periods** — Custom on-sale windows are copied
- **Zones** — Access control zones are replicated
- **Sale item groups** — Groupings are preserved
- **Timeslots** — Time divisions within the event
- **Data capture questions** — Customer questions are copied
- **Internal questions** — Staff-facing questions and responses

### Publishing

In the **Schedule repeats** modal, the **Publish** toggle (*Do you want the new event(s) to be published immediately?*) controls how new events are created:

- **On** — Events go live as they are created
- **Off** (default) — Events are created as drafts, allowing you to publish them individually
