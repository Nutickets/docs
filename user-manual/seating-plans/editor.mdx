## Overview

The seating plan editor is the authoring workspace for building and maintaining reusable plan schemas.

This page focuses on creation and design tooling:

- Drawing areas, blocks, rows, tables, and general admission areas
- Configuring labels, metadata, and visual behavior
- Managing object-level properties and plan-level settings
- Running plan checks before save/export

Operational event workflows (assigning plans to events, event availability, event pricing allocation, holds at event level) are documented in [Seated Events](/user-manual/event-management/seated-events).

## Editor Surface

| Workspace area             | What it is for                                                                                      |
| -------------------------- | --------------------------------------------------------------------------------------------------- |
| **Top menu**               | Plan-level actions, edit commands, view controls, seat tools, and label tooling                     |
| **Object menu (left)**     | Add/draw new plan objects (areas, blocks, tables, GA, text, shapes, icons)                          |
| **Canvas**                 | Draw, select, move, resize, reorder, and visually inspect the layout                                |
| **Settings panel (right)** | Configure selected objects and plan metadata (price bands, gates, stairs, stands, tags)             |
| **Plan information modal** | Stats, duplicate label checks, preview generation, rendering version, area-wide maintenance actions |

#### Display Area Content

<Tip>New in Release 47</Tip>

On large plans, areas are normally drawn as plain boundary shapes, and you open an area to see and edit the seats inside it. **Display area content** lets you show the objects inside areas — seats, tables, general admission, shapes, text, and icons — without opening each area, so you can see the whole venue laid out at once.

Open it from **Plan > Display area content**. The modal has three independent toggles, each set to **Enabled** or **Disabled**, that control where area content is shown:

| Toggle     | Controls where area content is shown                              |
| ---------- | ----------------------------------------------------------------- |
| **Editor** | The seating plan editor canvas while you build the plan           |
| **Admin**  | The [event plan dashboard](/user-manual/event-management/seated-events#plan-dashboard) used to manage a seated event |
| **Shop**   | The customer-facing plan in the ticket shop                       |

When a toggle is **Enabled**, the contents of areas that are not currently open are drawn in place. The content appears as outlines only — seat statuses, seat labels, and row labels are **not** shown for an area that is not open, and the area's own name label is hidden while its contents are visible. Opening an area still shows that area in full detail, with statuses, labels, and colours.

When a toggle is **Disabled**, areas that are not open are drawn as plain boundary shapes with their area name, and you open an area to see what is inside it.

<Note>
  Defaults differ by plan age. New large plans start with **Editor** and **Admin** enabled and **Shop** disabled. Existing plans have all three toggles disabled until you turn them on.
</Note>

<Note>
  Showing area content for large plans is optimised so the whole venue can render smoothly — the contents of closed areas are cached and reused rather than redrawn continuously.
</Note>

### Hidden Vs Delete Seats

Use these two tools for different outcomes:

| Option     | Use it when                                                                   | Key behavior                                                                      |
| ---------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **Hidden** | You want seats out of sale/customer view but may need them back later         | Seats stay in the plan structure and keep their labels; unhide is available later |
| **Delete** | You are making structural plan changes and want seats removed from the schema | Seats are marked as deleted, labels are removed, and restore requires delete mode |

### Deletion Limits And Guardrails

- **Attached-event limitation:** once a plan has already been synced to events, existing synced seats cannot be deleted in the editor. Use **Hidden** instead for operational removals.
- **Capacity limitation:** you cannot **unhide** or **restore** seats when the plan is already at its hard seat limit.
- **Mutual exclusivity:** setting seats to hidden clears deleted state, and deleting seats clears hidden state.
- **Restore workflow:** use **Show deleted seats** to select deleted seats before running **Restore selected seats**.

If your goal is event-level availability management (rather than changing plan structure), use event seat statuses in [Seated Events](/user-manual/event-management/seated-events).

## Plan Information Modal (Plan stats)

**Plan information** is a maintenance/QA workspace, not only a stats readout. Open it with the **Plan stats** button in the editor header, or from **Plan > Plan information** in the top menu.

It provides:

- Scope switch between **Whole plan details** and individual area stats (large plans)
- Plan preview generation/regeneration image
- Duplicate seat label detection with direct seat-jump actions
- Object and capacity counts (areas, blocks, rows, tables, seats, GA, accessible)
- Usage breakdowns under **Price band details**, and equivalent gate, stair, stand, and tag sections — each row shows the band or item name plus **No of seats** and **No of general admission spaces** counters
- Restore actions when referenced metadata items are missing
- Rendering version selector (with version help text)

Footer actions:

- **Save all areas**
- **Recalculate labels**

<Note>
  **Plan stats** is disabled while an area is open on a large plan — use **Save & back** to return to the main plan first. Opening the modal on a large plan loads every area, so the whole-plan counters include seats inside areas.
</Note>

### Deleting A Price Band

Price bands are deleted from **Plan information**, not from the **Price bands** tab in the settings panel. A band can only be removed once nothing on the plan is using it.

1. Free up the band first. Select the seats or general admission blocks still assigned to it and apply a different band from the **Price bands** tab in the settings panel, or delete those objects.
2. Close any open area, then open **Plan stats** from the editor header.
3. Leave the scope selector on **Whole plan details**.
4. Find the band under **Price band details**. When nothing is using it, both counters read `0` and a **Delete** link appears next to its name.
5. Click **Delete**. The band disappears from the list immediately and the counts refresh.
6. Save the plan to persist the change.

The **Delete** link only appears when all of the following are true:

- The plan is not attached to any [event](/user-manual/event-management/seated-events). Once any event uses the plan, price bands can no longer be deleted.
- The scope is set to **Whole plan details** — the link is hidden while viewing an individual area's stats.
- **No of seats** reads `0` for that band.
- **No of general admission spaces** reads `0` for that band.

<Note>
  A plan always keeps at least one price band, and the band the plan was created with cannot be deleted. If both counters read `0` but **Delete** does not remove the band, it is the plan's original band — rename it from the **Price bands** tab and reuse it instead.
</Note>

<Note>
  If seats still point at a band that is no longer on the plan, **Price band details** lists it as **MISSING PRICE BAND** with a **Restore** action that adds a price band back to the plan so those seats have a band to reference again.
</Note>

- Color
- Description
- Used as filter
- Used as tooltip
- Show as ticket info

## Tips And Shortcuts

The settings panel exposes shortcut guidance for selected objects, including:

- Rotate by small increments with modifier + left/right arrows
- Rotate by larger increments with modifier + up/down arrows
- Move objects with arrow keys
- Increase move distance with `Shift`

## Guardrails And Limits

- Seat/space hard limits block further creation once reached.
- Input controls for block/table/row creation clamp to allowed ranges.
- Some operations are constrained when plans have events/sales attached.
- Area deletion is restricted for saved areas when events are attached.
- [Price band deletion](#deleting-a-price-band) requires that no event uses the plan and that no seats or general admission spaces are assigned to the band.
- Image-in-shop toggles are disabled above file-size threshold.
